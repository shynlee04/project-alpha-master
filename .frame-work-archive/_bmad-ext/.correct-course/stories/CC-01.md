# Story CC-01: Remove Hardcoded API Keys

**Story ID**: CC-01
**Priority**: P0 (Security Critical)
**Effort**: 1 hour
**Validator**: analyst-ext
**Status**: pending

---

## Description

Remove hardcoded Gemini API keys from source code files and use the credential vault pattern instead.

### User Story

As a security-conscious developer,
I want to remove hardcoded API keys from the source code,
So that sensitive credentials are not exposed in the repository and follow the BYOK (Bring Your Own Key) architecture.

---

## FR (Functional Requirements)

1. Remove hardcoded API key from `src/lib/init/seed-workspace-permissions.ts`
2. Remove hardcoded API key from `src/lib/agent/providers/agent-validation-service.ts`
3. Verify all API calls use credential vault pattern
4. Ensure existing users can migrate to the vault pattern

---

## NF (Non-Functional Requirements)

### Security
- No hardcoded credentials in source (grep for "AIzaSy" returns 0)
- Credentials stored in encrypted vault
- Follows BYOK architecture (ADR-033 D7-D9)

### Performance
- No impact on runtime performance
- Vault access is cached

### Compliance
- API key rotation procedure documented
- Error handling when vault is empty

---

## Edge Cases

1. **Existing users with hardcoded keys**: Migration path must exist
2. **API key rotation**: Procedure documented
3. **Vault empty**: Proper error handling
4. **Development/testing**: Environment key handling
