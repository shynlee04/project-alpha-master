# ADR-037: XSS Sanitization Strategy

**Status**: PROPOSED
**Date**: 2026-01-18
**Author**: architect-ext

## Issue

The codebase has **5+ instances** of `dangerouslySetInnerHTML` without proper XSS sanitization. Additionally, 2 more XSS vectors were identified in iframe-based rendering, bringing the total attack surface to **7 vulnerable locations**.

### Vulnerable Files Identified

| File | Line(s) | Risk Level | Description |
|------|---------|------------|-------------|
| `StreamdownRenderer.tsx` | 124 | Medium | `dangerouslySetInnerHTML` with loose security level |
| `DeepThinkUI.tsx` | 221-222 | High | Naive `renderMarkdown()` without sanitization |
| `ChartDiagramBlock.tsx` | 502 | Medium | `dangerouslySetInnerHTML` for Mermaid SVG |
| `CommandPalette.tsx` | 269-270 | High | `dangerouslySetInnerHTML` for command descriptions |
| `RAGSearchPanel.tsx` | 63 | Medium | `dangerouslySetInnerHTML` with biome-ignore |
| `ArtifactBlock.tsx` | 257-263 | Critical | `iframe` with `srcdoc` containing unsanitized HTML/CSS/JS |
| `ArtifactPreviewModal.tsx` | 226-235 | Critical | `doc.write(code)` for HTML/SVG preview |

### Current State

- **DOMPurify**: NOT INSTALLED
- **rehype-sanitize**: Installed but UNUSED in vulnerable files
- **renderMarkdown()**: Naive regex-based renderer with NO XSS protection

## Analysis

### Evidence from Validation Reports

**Paper 2 Validation (Claim 4)**:
> "Exactly 5 instances found without DOMPurify: `StreamdownRenderer.tsx` (124), `DeepThinkUI.tsx` (221-222), `ChartDiagramBlock.tsx` (502), `CommandPalette.tsx` (269-270), `RAGSearchPanel.tsx` (63). DOMPurify NOT installed, `rehype-sanitize` installed but unused."

**Discrepancy Found**:
> "Paper 2 undercounted XSS attack surface by not considering iframe and doc.write patterns."

**Past Fix Attempts**:
> "No sanitization implemented for dangerouslySetInnerHTML usages. Critical vulnerability remains."

### Attack Vectors

1. **Markdown Injection**: User-provided markdown can contain script tags
   ```typescript
   function renderMarkdown(markdown: string): string {
     // Basic markdown rendering - NO XSS SANITIZATION
     return markdown
       .replace(/^### (.*$)/gim, '<h3>$1</h3>')
       // ... naive regex replacements - VULNERABLE TO XSS
   }
   ```

2. **Iframe srcdoc**: Direct HTML/CSS/JS injection
   ```typescript
   <iframe srcdoc={unsanitizedHtml} />
   ```

3. **doc.write()**: Direct document manipulation
   ```typescript
   doc.write(code); // code can contain malicious scripts
   ```

## Decision

Implement DOMPurify as the canonical XSS sanitization library for all HTML rendering in the application.

### Why DOMPurify

| Factor | Assessment |
|--------|------------|
| **Security** | Industry-standard, actively maintained |
| **Bundle Size** | ~20KB gzipped, acceptable |
| **Performance** | Fast, configurable whitelist |
| **Compatibility** | Works with React, no SSR issues |
| **Alternative (rehype-sanitize)** | Unused, requires unified MDX pipeline |

### Proposed Solution

1. **Install DOMPurify**
2. **Create sanitization utilities** for different contexts
3. **Sanitize all 7 vulnerable locations**
4. **Add configuration for trusted content (e.g., Mermaid SVG)**

## Consequences

### Positive
- Eliminates XSS vulnerabilities in all 7 locations
- Industry-standard security posture
- Centralized sanitization logic
- Configurable for different trust levels

### Negative
- Additional bundle size (~20KB)
- Performance overhead for sanitization
- Must educate developers on when NOT to bypass
- Some edge cases may need custom handling

### Neutral
- Does not affect non-HTML content
- Consistent with security best practices

## Implementation

### Step 1: Install DOMPurify

```bash
pnpm add dompurify
pnpm add -D @types/dompurify
```

### Step 2: Create sanitization utilities

```typescript
// src/infrastructure/security/sanitization.ts

import DOMPurify from 'dompurify';

// Default sanitization for user-provided content
export function sanitizeHtml(html: string): string {
  return DOMPurify.sanitize(html, {
    ALLOWED_TAGS: [
      'h1', 'h2', 'h3', 'h4', 'h5', 'h6',
      'p', 'br', 'hr',
      'strong', 'em', 'u', 's', 'del', 'ins',
      'ul', 'ol', 'li',
      'a', 'code', 'pre',
      'blockquote',
    ],
    ALLOWED_ATTR: ['href', 'title', 'class'],
    ALLOW_DATA_ATTR: false,
  });
}

// For Mermaid SVG (trusted source but external)
export function sanitizeSvg(svg: string): string {
  return DOMPurify.sanitize(svg, {
    ALLOWED_TAGS: ['svg', 'g', 'path', 'rect', 'circle', 'text', 'foreignObject'],
    ALLOWED_ATTR: ['class', 'd', 'fill', 'stroke', 'width', 'height', 'x', 'y'],
  });
}

// For iframe srcdoc (most restrictive)
export function sanitizeIframeContent(html: string): string {
  return DOMPurify.sanitize(html, {
    ALLOWED_TAGS: ['div', 'span', 'p', 'br'],
    ALLOWED_ATTR: ['class', 'style'],
    ALLOW_DATA_ATTR: false,
  });
}
```

### Step 3: Fix DeepThinkUI.tsx (High Risk)

```typescript
// BEFORE
<div
  className="prose prose-sm max-w-none"
  dangerouslySetInnerHTML={{ __html: renderMarkdown(response) }}
/>

// AFTER
import { sanitizeHtml } from '@/infrastructure/security/sanitization';

  className="prose prose-sm max-w-none"
  dangerouslySetInnerHTML={{ __html: sanitizeHtml(renderMarkdown(response)) }}
```

## Security Considerations

### Trust Levels

| Context | Trust Level | Sanitization |
|---------|-------------|--------------|
| User-generated markdown | Untrusted | Full sanitizeHtml |
| AI response content | Untrusted | Full sanitizeHtml |
| Mermaid SVG output | Semi-trusted | sanitizeSvg |
| Command descriptions | Untrusted | Full sanitizeHtml |
| Artifact preview | Untrusted | sanitizeIframeContent |

### Configuration Options

```typescript
// For enhanced security in admin contexts
const strictConfig = {
  ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'p'],
  ALLOWED_ATTR: [],
  ALLOW_DATA_ATTR: false,
};
```
