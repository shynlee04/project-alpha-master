# ADR-036: Foundation Cleanup & Infrastructure Consolidation

**Status:** PROPOSED
**Date:** 2026-01-15
**Author:** Architecture Documentation Agent

## Context

The project currently suffers from a "Split Brain" architecture where persistence logic is scattered between legacy `src/lib` utilities and the new `src/infrastructure` layer. Additionally, several "God Stores" (oversized Zustand stores handling too many responsibilities) exist, making maintenance and testing difficult.

To align with the Clean Architecture principles defined in ADR-033, we must consolidate all persistence logic into `src/infrastructure` and refactor monolithic stores into focused slices.

## Decisions

### 1. Slash Command Store Migration
*   **Decision:** Move `src/lib/notes/slash-command-store.ts` to `src/infrastructure/persistence/stores/notes/slash-commands/`.
*   **Implementation:** The new store must use the `createDexieStorage` middleware to ensure data is persisted to IndexedDB instead of `localStorage`.

### 2. Thread Persistence Migration
*   **Decision:** Extract the `saveThread` and related persistence logic from `src/lib/workspace/threads-store.ts`.
*   **Implementation:** Move this logic to a dedicated persistence adapter at `src/infrastructure/persistence/stores/conversation/persistence.ts`. The store should delegate saving/loading to this adapter.

### 3. Chat Store Refactor
*   **Decision:** Split the monolithic `unified-chat-store.ts`.
*   **Implementation:** Extract the persistence-specific logic into a separate slice named `chat-persistence-slice.ts` within the same directory structure in `src/infrastructure`. This separates state management from data persistence.

### 4. Smart Note Import
*   **Decision:** Optimize the `NoteFolderBridge` to prevent unnecessary processing.
*   **Implementation:** Implement `lastModified` timestamp checks. The bridge should only re-parse and import notes if the file on disk has a newer modification time than the record in the database.

## Consequences

### Positive
*   **Eliminates localStorage:** Critical application data will no longer rely on the limited and synchronous `localStorage` API, moving to the more robust IndexedDB.
*   **Decoupling:** UI components will interact with clean interfaces rather than being tightly coupled to legacy implementation details.
*   **Performance:** Desktop sync performance will improve significantly by avoiding redundant processing of unchanged files.
*   **Archival Readiness:** These changes are a prerequisite for safely archiving the deprecated `src/lib/workspace` directory.

### Negative
*   **Refactoring Effort:** Requires careful migration of existing data and updates to all call sites referencing the old stores.
*   **Temporary Instability:** Risk of regressions during the migration of core persistence logic, requiring thorough testing.
