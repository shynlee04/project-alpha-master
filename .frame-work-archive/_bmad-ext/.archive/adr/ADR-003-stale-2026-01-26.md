# ADR-003: Clean Architecture Layer Separation

**Status**: PROPOSED  
**Date**: 2026-01-07  
**Decision Type**: Architectural Standard

## Context

Phase 1 analysis revealed 75% Clean Architecture compliance:
- **Core** (4 entities) - Minimal, well-defined
- **Domain** (7 services) - Partial, needs expansion
- **Infrastructure** (250+ files) - Largest, well-organized
- **Presentation** (474 components) - Dominant, needs separation

## Decision

Enforce **strict 4-layer architecture** with clear boundaries and dependency rules.

### Layer Definitions

```
┌─────────────────────────────────────────────────────────┐
│ PRESENTATION LAYER (src/presentation/)                  │
│ Responsibilities: UI components, hooks, render logic    │
│ Dependencies: None (imports from Domain)                │
│ Rules: No business logic, only UI state management      │
├─────────────────────────────────────────────────────────┤
│ DOMAIN LAYER (src/domain/)                              │
│ Responsibilities: Business logic, use-cases, services   │
│ Dependencies: Core only                                 │
│ Rules: Pure TypeScript, no React, no infrastructure     │
├─────────────────────────────────────────────────────────┤
│ CORE LAYER (src/core/)                                  │
│ Responsibilities: Entities, value objects, types        │
│ Dependencies: None                                      │
│ Rules: Pure data structures, no logic                   │
├─────────────────────────────────────────────────────────┤
│ INFRASTRUCTURE LAYER (src/infrastructure/)              │
│ Responsibilities: Persistence, events, external services│
│ Dependencies: All layers (adapter pattern)              │
│ Rules: Implements interfaces from Domain                │
└─────────────────────────────────────────────────────────┘
```

### Dependency Flow

```
PRESENTATION → DOMAIN → CORE
                    ↓
              INFRASTRUCTURE (implements Domain interfaces)
```

### Forbidden Patterns

```typescript
// ❌ FORBIDDEN - Presentation imports Infrastructure directly
// src/presentation/components/ide/MyComponent.tsx
import { db } from '@/infrastructure/persistence/'; // ❌

// ✅ CORRECT - Presentation imports Domain service
import { AgentService } from '@/domain/services/';

// ❌ FORBIDDEN - Domain imports Infrastructure
// src/domain/services/my-service.ts
import { db } from '@/infrastructure/persistence/'; // ❌

// ✅ CORRECT - Domain defines interface, Infrastructure implements
// src/domain/services/my-service.ts
interface AgentRepository {
  getAgent(id: string): Promise<Agent>;
}

// src/infrastructure/persistence/agent-repository.ts
import { AgentRepository } from '@/domain/services/';
export class AgentRepositoryImpl implements AgentRepository { ... }

// ❌ FORBIDDEN - Core contains logic
// src/core/entities/Agent.ts
class Agent {
  validate(): boolean { ... } // ❌ Logic in Core
}

// ✅ CORRECT - Core is pure data, logic in Domain
// src/core/entities/Agent.ts
interface Agent {
  id: string;
  name: string;
}

// src/domain/services/agent-validator.ts
function validateAgent(agent: Agent): boolean { ... }
```

### Layer Size Targets

| Layer | Current Files | Target Files | Target Lines/File |
|-------|--------------|--------------|-------------------|
| Core | 4 | 10-15 | 50-100 |
| Domain | 7 | 20-30 | 100-200 |
| Infrastructure | 250+ | 300+ | 100-200 |
| Presentation | 474 | 500+ | <300 |

## Rationale

1. **Testability**: Pure domain logic without React/infrastructure
2. **Maintainability**: Clear boundaries, single responsibility
3. **Reusability**: Domain logic usable outside React
4. **Flexibility**: Swap infrastructure implementations

## Compliance Checklist

- [ ] No presentation-to-infrastructure imports
- [ ] Domain defines interfaces, Infrastructure implements
- [ ] Core contains only data structures (no logic)
- [ ] All cross-layer dependencies use adapter pattern
- [ ] No god components in presentation (>300 lines)
