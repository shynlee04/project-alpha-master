## Executive Summary

## Scenario A: Hub Create Button

### Flow
1. User clicks "Create Project" on HubHomePage
2. Navigate to `/hub?action=create-project`
3. Hub detects action parameter
4. Shows project creation dialog
5. User fills form (name, workspace bindings, etc.)
6. `db.projects.put()` stores project
7. Navigate to project-specific route

### Key Files
| Step | File |
|------|------|
| Create button | HubHomePage.tsx |
| Action detection | hub.tsx or search params |
| Project creation | `db.projects.put()` |
| Navigation | TanStack Router |

## Scenario B: Notes Auto-Create

### Flow
1. User navigates to `/notes`
2. `StableNotesWorkspace` loads
3. Uses **hardcoded** projectId: `'default-notes'`
4. Calls `loadNotes(projectId)` with `'default-notes'`
5. If no notes exist, creates new notes in memory

### Key Code (notes.lazy.tsx:77)
```typescript
const projectId = 'default-notes';

useEffect(() => {
  loadNotes(projectId);
}, [projectId, loadNotes]);
```

### Conflict Risk
| Aspect | Value |
|--------|-------|
| Project ID | `default-notes` (hardcoded) |
| Project Name | Unknown (not created in projects table) |
| Binding | Not set (notes only) |
| **Risk** | MEDIUM - Not a real project |

## Scenario C: IDE Auto-Create (Temp Project)

### Flow
1. User clicks "Quick IDE" or "Select Project Folder"
2. `handleCreateTemp()` or `FolderPickerDialog` triggered
3. Calls `getOrCreateTempProject()`
4. Creates temp project in `projects` table
5. Navigates to `/ide/$projectId`

### Key Code (ide.tsx:172-182)
```typescript
async function handleCreateTemp(navigate) {
  const tempProject = await getOrCreateTempProject();
  navigate({ to: '/ide/$projectId', params: { projectId: tempProject.id } });
}
```

### Temp Project Properties
| Property | Value |
|----------|-------|
| ID Format | `temp-ide` |
| Name | "Quick IDE" |
| Storage | `indexeddb` |
| Bindings | All enabled (`ide`, `knowledge`, `study`, `notes`) |
| Auto-created | Yes |

## Conflict Analysis

### Conflict 1: Multiple Project Creation Paths
| Path | Creates Real Project? | Table |
|------|----------------------|-------|
| Hub Create | ✅ Yes | projects |
| Notes Auto-Create | ❌ No | notes only |
| IDE Temp | ✅ Yes (temp) | projects |
| Knowledge | ❌ No | N/A |

### Conflict 2: Project ID Collision
| ID | Source | Notes |
|----|--------|-------|
| `temp-ide` | getOrCreateTempProject() | Temp project |
| `default-notes` | Hardcoded in Notes | Not in projects table |
| `temp-knowledge` | Not used (broken) | N/A |

### Conflict 3: Naming Convention
| Project Type | ID Pattern | Example |
|--------------|------------|---------|
| Real project | UUID or custom | `proj_abc123` |
| Temp project | `temp-{workspace}` | `temp-ide` |
| Notes default | Hardcoded | `default-notes` |

## Recommendations

### Immediate (P0)
1. **Audit `default-notes` projectId**
   - Convert to real project or remove
   - Add to projects table if needed

### Short-term (P1)
1. **Unify project creation**
   - Hub → IDE/Notes should use same path
   - Remove hardcoded projectIds

2. **Fix Knowledge workspace**
   - Re-implement useWorkspaceAccess
   - Allow project creation

### Long-term (P2)
1. **Create ProjectFactory**
   - Centralize project creation logic
   - Consistent naming conventions
   - Template support

2. **Add project validation**
   - Prevent duplicate IDs
   - Validate bindings
