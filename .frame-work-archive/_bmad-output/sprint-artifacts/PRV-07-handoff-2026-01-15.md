## Key Implementation Details

### Type Consolidation Pattern
Instead of duplicating the ModalityType definition in the adapter, we now:

1. Import the canonical `ModalityType` from the domain layer
2. Create a constrained subset using TypeScript's `Extract<>` utility type
3. Re-export from the facade for backward compatibility

```typescript
// BEFORE: Type duplication in adapter
export type ChutesModality = 'text' | 'image' | 'tts' | 'stt';

// AFTER: Domain-source with constrained subset
import type { ModalityType } from '@/domain/types/llm/provider-types';
export type ChutesModality = Extract<ModalityType, 'text' | 'image' | 'tts' | 'stt'>;
```

### Domain Layer Location
The canonical `ModalityType` is defined at:
```
src/domain/types/llm/provider-types.ts:32
```

```typescript
export type ModalityType = 'text' | 'image' | 'audio' | 'video' | 'tts' | 'stt';
```

### Why Extract<> instead of extending?
Using `Extract<ModalityType, 'text' | 'image' | 'tts' | 'stt'>` ensures:
- Type safety: Only valid ModalityType values can be used
- Single source of truth: Domain layer owns the definition
- Flexibility: Chutes can support a subset without defining new types
- Future-proof: If ModalityType adds new values, ChutesModality automatically doesn't include them
