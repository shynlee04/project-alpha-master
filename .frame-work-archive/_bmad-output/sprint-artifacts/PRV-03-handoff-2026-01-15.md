## Key Implementation Details

### Fallback Flow
1. Hook receives agent's configured `providerId`
2. First tries to get credentials for configured provider
3. If no key found, calls `getProviderWithKey()` which tries providers in priority order:
   - groq (fast, generous free tier)
   - openrouter (aggregator with free models)
   - google (Gemini with free tier)
   - openai (industry standard)
   - anthropic (Claude - usually paid)
   - mistral (Mistral AI)
   - chutes (Chutes.ai)
4. Returns first provider with valid API key
5. Shows bilingual toast if fallback occurred

### Notification Deduplication
Uses `useRef` to track which provider was notified, preventing duplicate toast notifications when the hook re-runs.

### Bilingual Support
Fallback messages use i18n keys:
- `agentKey.fallbackNotice`: "Using {fallbackProvider} instead of {originalProvider} (no API key configured)"
- `agentKey.fallbackUnavailable`: "No API key available for {provider} or any fallback providers"
