1 # Architecture Overview
2
3 This document describes the high-level architecture of the project-alpha
4 application. It follows Clean Architecture principles with a clear separation
5 of concerns between layers.
6
7 ## Core Principles
8
9 | Principle | Description |
10 |-----------|-------------|
11 | Separation of Concerns | Each layer has a distinct responsibility |
12 | Dependency Inversion | High-level modules don't depend on low-level modules |
13 | Single Responsibility | Each class has one reason to change |
14 | Explicit Dependencies | Dependencies are declared and injected |
15
16 ## Layer Structure
17
18 ```
19 ┌─────────────────────────────┐
20 │ Presentation Layer │ // React Components, Hooks
21 ├─────────────────────────────┤
22 │ Domain Layer │ // Entities, Services, Interfaces
23 ├─────────────────────────────┤
24 │ Infrastructure Layer │ // Database, API, External Services
25 └─────────────────────────────┘
26 ```
27
28 ### 1. Presentation Layer
29
30 The presentation layer is responsible for:
31
32 - Rendering UI components with React
33 - Managing local component state
34 - Handling user interactions
35 - Connecting to domain services
36
37
39
40 Contains business logic that is independent of frameworks:
41
42 - **Entities**: Core business objects (Project, User, Note)
43 - **Services**: Business logic and use cases
44 - **Interfaces**: Abstractions for infrastructure
45 - **Types**: TypeScript types and interfaces
46
47 ### 3. Infrastructure Layer
48
49 Handles external concerns and integrations:
50
51 - **Persistence**: Dexie.js database operations
52 - **File System**: FSA API for desktop, IndexedDB for mobile
53 - **Sync**: Cross-device synchronization logic
54 - **Events**: Event bus for loose coupling
55
