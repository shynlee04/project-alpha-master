## Description

Implement a plugin registry that manages plugin registration, retrieval, and discovery. The registry follows a singleton pattern and provides filtering capabilities based on context requirements (storage type, device type).

---

## User Story

**As a** plugin system architect,
**I want** a centralized registry that can store, retrieve, and filter plugins based on their requirements,
**So that** the application can dynamically load compatible plugins for each project context without hard-coding plugin logic.

---

## Acceptance Criteria

### AC1: registerPlugin() stores plugin in Map
**Given:** A valid FeaturePlugin object with id, name, requirements, and components
**When:** registerPlugin() is called with this plugin
**Then:**
- Plugin is stored in internal Map with PluginId as key
- If plugin with same id already exists, console warning is logged
- Existing plugin is overwritten with new instance
- No errors are thrown

### AC2: getPlugin() retrieves by PluginId
**Given:** One or more plugins registered in the registry
**When:** getPlugin() is called with a specific PluginId
**Then:**
- Returns the FeaturePlugin object if plugin exists
- Returns undefined if plugin does not exist
- Returns exact match from registry Map (not a copy)

### AC3: getAvailablePlugins() filters by context requirements
**Given:** Multiple plugins registered with different storage and device requirements
**When:** getAvailablePlugins() is called with a ProjectContext
**Then:**
- Returns array of plugins compatible with both storageType and deviceType
- Filters out plugins with storageType requirement that doesn't match context
- Filters out plugins with deviceType requirement that doesn't match context
- Includes plugins with 'any' for either requirement
- Returns empty array if no plugins are compatible

### AC4: Singleton pattern for registry
**Given:** The plugin-registry module is loaded
**When:** Multiple parts of the application import registry functions
**Then:**
- Only one registry Map instance exists (module-level const)
- All imports share the same plugin data
- No class instantiation required
- Internal Map is not directly accessible (encapsulated)

**When:** TypeScript compiler runs on the files
**Then:**
- No TypeScript errors
- All function signatures properly typed

## Technical Specifications

### plugin-registry.ts

```typescript
import type { FeaturePlugin, ProjectContext, PluginId } from '@/domain/interfaces/feature-plugin.interface';

// Singleton registry instance (private)
const pluginRegistry = new Map<PluginId, FeaturePlugin>();

/**
 * Register a plugin in the registry.
 * @param plugin - Plugin to register
 */
export function registerPlugin(plugin: FeaturePlugin): void {
  if (pluginRegistry.has(plugin.id)) {
    console.warn(`Plugin ${plugin.id} already registered, overwriting`);
  }
  pluginRegistry.set(plugin.id, plugin);
}

/**
 * Get a plugin by its ID.
 * @param id - Plugin ID to retrieve
 * @returns Plugin or undefined if not found
 */
export function getPlugin(id: PluginId): FeaturePlugin | undefined {
  return pluginRegistry.get(id);
}

/**
 * Get all plugins compatible with the given project context.
 * @param context - Project context to filter against
 * @returns Array of compatible plugins
 */
export function getAvailablePlugins(context: ProjectContext): FeaturePlugin[] {
  return Array.from(pluginRegistry.values()).filter(plugin => {
    const { storageType, deviceType } = plugin.requirements;

    // Check storage type compatibility
    if (storageType !== 'any' && storageType !== context.project.storageType) {
      return false;
    }

    // Check device type compatibility
    if (deviceType !== 'any' && deviceType !== context.platform.deviceType) {
      return false;
    }

    return true;
  });
}

/**
 * Get all registered plugins (for debugging/inspection).
 * @returns Array of all registered plugins
 */
export function getAllPlugins(): FeaturePlugin[] {
  return Array.from(pluginRegistry.values());
}
```
