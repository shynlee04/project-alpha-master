## Acceptance Criteria

### AC-01: ChatPlugin implements FeaturePlugin interface
- [ ] `ChatPlugin` object implements `FeaturePlugin` interface from `@/domain/interfaces/feature-plugin.interface`
- [ ] Plugin definition includes all required properties:
  - [ ] id: 'chat'
  - [ ] name: 'Chat'
  - [ ] icon: ReactNode (MessageSquare or similar)
  - [ ] description: Brief description of plugin functionality
  - [ ] requirements: storageType='any', deviceType='any', minWidth=400, maxInstances='unlimited'
  - [ ] MainComponent: React component that receives PluginMainProps
  - [ ] Optional: SidebarComponent, ToolbarComponent (if needed)
  - [ ] Lifecycle hooks: onMount, onUnmount, onProjectChange

### AC-02: Available for all storage types and devices
- [ ] Plugin works with FSA (desktop) storage
- [ ] Plugin works with IndexedDB (mobile) storage
- [ ] Plugin works on desktop (deviceType: 'desktop')
- [ ] Plugin works on mobile (deviceType: 'mobile')
- [ ] Plugin requirements: `storageType: 'any'`, `deviceType: 'any'`

### AC-03: Persists threads per project
- [ ] Threads are filtered/loaded based on current `projectId` from ProjectContext
- [ ] Thread persistence uses existing `unified-chat-store` from `@/infrastructure/persistence/stores/chat`
- [ ] Thread switching works correctly within project context
- [ ] New threads created within current project scope
- [ ] Thread state persists across plugin mount/unmount cycles

### AC-04: Tool execution works with ProjectContext
- [ ] Tool execution receives project context from ProjectContext
- [ ] `openFile()` action from ProjectContext is accessible to chat for file operations
- [ ] `saveFile()` action from ProjectContext is accessible to chat for saving generated files
- [ ] Other ProjectContext actions (refreshFileTree, etc.) are accessible
- [ ] Tool results can trigger file operations in other plugins (Monaco, FileTree)

### AC-05: TypeScript compiles with 0 errors
- [ ] `pnpm tsc --noEmit` returns 0 errors
- [ ] No type errors in chat plugin files
- [ ] No import errors from existing chat components
- [ ] All type definitions are correct and export properly

### Chat-Specific Considerations

**Integration Points:**
- **Tool execution:** Via ProjectContext actions
- **File operations:** Via ProjectContext.openFile/saveFile
- **Thread persistence:** Via existing `unified-chat-store`
- **Multi-agent support:** Via `MultiAgentChatPanel` component (import from existing location)
- **Thread management:** Via `ThreadManager` component (import from existing location)

**Component Selection:**
For this POC, wrap existing `UnifiedChatPanel` or `AgentChatPanel` from presentation layer:
- Import: `@/presentation/components/chat/UnifiedChatPanel`
- Import: `@/presentation/components/chat/AgentChatPanel`
- Use `mode="agent"` for tool-enabled chat (recommended)
- Pass projectId from ProjectContext

**Thread Persistence:**
- Existing store: `@/infrastructure/persistence/stores/chat/unified-chat-store`
- Use thread management via store hooks (no need to re-implement)
- Threads are already scoped by workspaceType and conversationId
- For plugin, filter by projectId from ProjectContext
