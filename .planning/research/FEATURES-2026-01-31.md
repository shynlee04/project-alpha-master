# Feature Landscape

**Domain:** AI-Powered Development IDE
**Researched:** 2026-01-31

---

## Table Stakes

Features users expect. Missing = product feels incomplete.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| Project CRUD | Users must create/manage projects | Medium | Core of FileTree Operator |
| File browsing/editing | IDE requires file tree | Medium | Core of FileTree Operator |
| AI chat interface | Promised core value | High | Chat-Cascade Operator |
| Code editor (desktop) | IDE without editor = useless | High | Monaco integration |
| Syntax highlighting | Standard IDE feature | Low | Monaco provides this |
| Multi-file context | AI needs file context | Medium | Context picker in chat |
| API key management | BYOK model requires vault | Medium | Encrypted storage |
| Cross-session persistence | Users expect state to survive refresh | Medium | Dexie + FSA |
| Mobile-responsive UI | Modern expectation | Medium | Platform-aware modules |

## Anti-Features

Features to explicitly NOT build. Common mistakes in this domain.

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| Server-side storage | Violates privacy promise | Client-side only (IndexedDB, FSA) |
| Single AI provider lock-in | Limits user choice | Multi-provider with BYOK |
| All features on mobile | Poor UX, performance issues | Platform-aware module loading |
| Over-permission prompts | UX friction | Smart defaults, batch permissions |
| Re-sync on every refresh | Performance killer | Persistent handles, smart invalidation |
| Monolithic plugin architecture | Spaghetti dependencies | Clear operator-module separation |
| Unlimited concurrent plugins | Conflicting writes, confusion | Limited slots, clear responsibilities |

## Feature Dependencies

```
PROJECT (root)
    ├── FileTree Operator (REQUIRED)
    │   └── Monaco Module (optional, desktop only)
    │   └── Terminal Module (optional, desktop only)
    │       └── Preview Module (optional, requires Terminal)
    ├── Chat-Cascade Operator (REQUIRED)
    │   └── RAG System (optional, enhances Chat)
    │   └── Tool Execution (required for agentic features)
    └── Notes Module (optional, all platforms)
        └── Notes AI Features (optional, enhances Notes)
```

**Dependency Rules:**
- FileTree and Chat-Cascade are OPERATORS (always running)
- Monaco requires FileTree (reads files)
- Terminal requires FileTree (modifies files)
- Preview requires Terminal (runs dev server)
- RAG requires FileTree + Chat-Cascade (indexes files, responds in chat)
- Tool Execution requires FileTree (creates/modifies files)

---

## MVP Recommendation

For MVP, prioritize:

1. **FileTree Operator** - Project and file CRUD, sync
2. **Chat-Cascade Operator** - Thread management, AI calls
3. **Tool Execution** - Basic read/write tools
4. **Monaco Module** - Code editing (desktop)
5. **Notes Module** - Rich text (all platforms)

Defer to post-MVP:
- **RAG System** - Requires working file system first
- **Terminal/Preview** - WebContainer integration complexity
- **Advanced tools** - Run commands, complex multi-step
