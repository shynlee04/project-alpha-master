# Architecture

**Analysis Date:** 2026-01-31

## Pattern Overview

**Overall:** Clean Architecture with Feature Plugin System (ADR-034)

**Key Characteristics:**
- Project-Centric architecture replacing Workspace-Centric model
- Clean Architecture layers: Presentation → Domain ← Infrastructure
- Feature Plugin system for extensible UI (filetree, monaco, notes, terminal, chat, agents, preview)
- Platform-first design: Desktop (FSA) vs Mobile (IndexedDB) separation
- Single Project Route (`/$projectId`) replacing 9 legacy routes
- 4-Layer State Architecture: UI State → Session State → Persisted State → File State

## Layers

**Presentation Layer:**
- Purpose: React UI components, layouts, and hooks
- Location: `src/presentation/`
- Contains: React components, custom hooks, layout containers, CSS modules
- Depends on: Domain interfaces, Infrastructure stores (via hooks)
- Used by: Routes for rendering

**Domain Layer:**
- Purpose: Business logic, entities, and contracts
- Location: `src/domain/`
- Contains: Entities (Project, Agent, Chat), services, types, interfaces
- Depends on: Nothing (pure domain)
- Used by: Presentation and Infrastructure layers

**Infrastructure Layer:**
- Purpose: External integrations, persistence, platform adapters
- Location: `src/infrastructure/`
- Contains: Dexie database, Zustand stores, FSA adapters, sync services, event bus
- Depends on: Domain interfaces (implements them)
- Used by: Presentation hooks, ProjectContext

**Routes Layer:**
- Purpose: TanStack Router route definitions
- Location: `src/routes/`
- Contains: Route components with loaders, lazy routes, API routes
- Depends on: Presentation components, Infrastructure stores
- Used by: Router for navigation

## Data Flow

**Project Loading Flow:**

1. User navigates to `/$projectId`
2. Route loader calls `waitForHydration()` then queries Dexie
3. `fromRecord()` converts ProjectRecord → Project domain entity
4. `ProjectContextProvider` initializes storage gateway based on storageType
5. Platform detection determines default plugins and layout
6. `ResponsiveLayout` renders with 6-column grid system
7. Plugin panels render active plugins via `PluginPanelContainer`

**File Operation Flow:**

1. Plugin (Monaco/Notes) calls `projectContext.saveFile(path, content)`
2. ProjectContext routes to StorageGateway
3. Gateway delegates to StorageAdapter (FSA or IndexedDB)
4. File change event emitted via event bus
5. FileTree plugin refreshes on event

**State Management:**
- UI State: Zustand stores with `useShallow` selectors (mandatory)
- Session State: React context (ProjectContext, PluginCoordinationContext)
- Persisted State: Dexie IndexedDB with Zustand persist middleware
- File State: FSA for desktop (real files) or IndexedDB for mobile (virtual files)

## Key Abstractions

**FeaturePlugin Interface:**
- Purpose: Contract for all feature plugins in the system
- Examples: `src/plugins/filetree/`, `src/plugins/monaco/`, `src/plugins/notes/`
- Pattern: Plugin registration via `registerPlugin()` in `plugin-registry.ts`
- Location: `src/domain/interfaces/feature-plugin.interface.ts`

**StorageAdapter Interface:**
- Purpose: Abstract file I/O regardless of storage backend
- Examples: `src/infrastructure/filesystem/fsa-storage-adapter.ts`, `src/infrastructure/filesystem/local-fs-adapter.ts`
- Pattern: Factory pattern via `StorageAdapterFactory`
- Location: `src/domain/interfaces/storage-adapter.interface.ts`

**StorageGateway Interface:**
- Purpose: High-level file operations for plugins
- Examples: `src/infrastructure/filesystem/fsa-gateway.ts`, `src/infrastructure/filesystem/idb-gateway.ts`
- Pattern: Facade over StorageAdapter with caching/batching
- Location: `src/domain/interfaces/storage-gateway.interface.ts`

**ProjectContext:**
- Purpose: Unified context for all plugins within a project
- Examples: Consumed via `useProjectContext()` hook
- Pattern: React Context with gateway, platform, and shared services
- Location: `src/infrastructure/context/project-context.tsx`

## Entry Points

**Application Bootstrap:**
- Location: `src/routes/__root.tsx`
- Triggers: TanStack Router initialization
- Responsibilities: Initialize Sentry, global error handlers, theme provider, locale, overlays, workspace provider

**Router Definition:**
- Location: `src/router.tsx`
- Triggers: Imported by TanStack Start
- Responsibilities: Create router instance, scroll restoration, export singleton

**Server Entry (SSR):**
- Location: `src/server.ts`
- Triggers: TanStack Start SSR
- Responsibilities: Server-side rendering entry point

**Route Tree:**
- Location: `src/routeTree.gen.ts`
- Triggers: Auto-generated by TanStack Router CLI
- Responsibilities: Type-safe route definitions

**Main Project Route:**
- Location: `src/routes/$projectId.tsx`
- Triggers: Navigation to `/{projectId}`
- Responsibilities: Load project, initialize context, render ResponsiveLayout

## Error Handling

**Strategy:** Error Boundaries at route and component level with global error handlers

**Patterns:**
- `AppErrorBoundary` wraps entire app in `__root.tsx`
- Route-level `ErrorBoundary` wraps `UnifiedProjectRoute`
- `initGlobalErrorHandlers()` for unhandled exceptions
- Sentry integration for production error tracking
- `DatabaseRecoveryDialog` for Dexie migration failures

## Cross-Cutting Concerns

**Logging:**
- Console logging with context prefixes (e.g., `[ProjectRoute.loader]`)
- Sentry for production error/performance monitoring

**Validation:**
- TypeScript strict mode enforced
- Type guards for plugin IDs (`isValidPluginId`)
- Domain-level validation in services

**Authentication:**
- API key management via secure storage (CredentialRecord in Dexie)
- Provider validation via `AgentProviderValidator`

**Internationalization:**
- i18next with `LocaleProvider` in root
- English (en) + Vietnamese (vi) support
- Location: `src/i18n/`

**Event Bus:**
- Domain events via `eventBus` (pub/sub pattern)
- File events via `file-event-bus.ts`
- Cross-workspace events via `cross-workspace-event-bus.ts`
- Location: `src/infrastructure/events/`

## Plugin System Architecture

**Plugin Registry:**
- Singleton map of registered plugins
- Location: `src/infrastructure/plugins/plugin-registry.ts`
- Functions: `registerPlugin()`, `getPluginById()`, `getFilteredPlugins()`

**Platform Defaults:**
- Location: `src/infrastructure/plugins/platform-defaults.ts`
- Desktop (FSA): Monaco as main, FileTree left, Chat right
- Desktop (IndexedDB): Notes as main, FileTree left, Chat right
- Mobile/Tablet: Notes only, single column

**Layout Store:**
- Zustand store with persist middleware
- Project-specific storage keys
- Location: `src/presentation/layouts/PluginLayoutStore.ts`

**Available Plugins:**
| Plugin ID | Location | Requirements |
|-----------|----------|--------------|
| `filetree` | `src/plugins/filetree/` | Any storage, any device |
| `monaco` | `src/plugins/monaco/` | FSA required, desktop |
| `notes` | `src/plugins/notes/` | Any storage, any device |
| `terminal` | `src/plugins/terminal/` | FSA required, desktop |
| `chat` | `src/plugins/chat/` | Any storage, any device |
| `preview` | `src/plugins/preview/` | Any storage, any device |

## Responsive Layout Grid

**Desktop (6-column):**
```
[0.5:0.5:2:4:2.5:0.5]
[GlobalSidebar:ActivityBarLeft:PanelLeft:MainPanel:PanelRight:ActivityBarRight]
```

**Tablet Landscape:**
```
[0.5:0.5:3:4:2:0.5]
```

**Mobile/Tablet Portrait:**
- Single panel + bottom navigation
- Plugin switching via BottomNavigation
