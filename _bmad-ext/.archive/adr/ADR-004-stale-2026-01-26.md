# ADR-004: God Component and Store Decomposition

**Status**: PROPOSED  
**Date**: 2026-01-07  
**Decision Type**: Remediation Strategy

## Context

Phase 1 analysis identified critical technical debt:
- **19 god components** exceed 300 lines (largest: 768 lines)
- **9 god stores** exceed 300 lines (largest: 1,169 lines)
- **1 critical file**: dexie-db.ts (1,169 lines) needs decomposition

## Decision

Implement **systematic decomposition strategy** with size limits and facade patterns.

### Size Limits

| Artifact Type | Max Lines | Max Functions |
|--------------|-----------|---------------|
| Component | 300 | 5 |
| Slice/Store | 120 | 10 |
| Hook | 150 | 3 |
| Utility | 120 | 5 |
| Test File | 400 | N/A |

## Rationale

1. **Maintainability**: Smaller files easier to understand
2. **Testability**: Pure functions, isolated units
3. **Reusability**: Extract reusable parts
4. **Performance**: Better tree-shaking
