## Recommended Stack

### Core Framework

| Technology | Version | Purpose | Why |
|------------|---------|---------|-----|
| TanStack Start | 1.157.3 | Full-stack React framework | File-based routing, SSR control, unified data loading. Already adopted. |
| TanStack Router | 1.157.3 | Client-side routing | Type-safe params, loader pattern, integrated with Start |
| React | 19.2.3 | UI library | Latest stable with concurrent features |
| TypeScript | 5.9.3 | Type safety | Strict mode, path aliases |

**Decision:** Keep TanStack Start. It provides the SSR flexibility needed (disable SSR per route for IndexedDB access) and integrates well with TanStack AI SDK.

### State Management

| Technology | Version | Purpose | Why |
|------------|---------|---------|-----|
| Zustand | 5.0.10 | Client-side state | Slices pattern, minimal boilerplate, `useShallow` for performance |
| Dexie.js | 4.2.1 | IndexedDB wrapper | Type-safe queries, `useLiveQuery` for reactivity, migrations |
| dexie-react-hooks | 4.2.0 | React integration | `useLiveQuery` hook for reactive Dexie queries |

**Critical Rules:**
- Zustand: NO persist middleware for entity data
- Dexie: ONLY persistence layer for entities
- State layer architecture: UI → Session → Persisted → File

### Storage

| Technology | Version | Purpose | When to Use |
|------------|---------|---------|-------------|
| File System Access API | Native | File read/write | Desktop browsers (Chrome, Edge, Safari 15.2+) |
| OPFS (Origin Private FS) | Native | Sandboxed file storage | Fallback when FSA unavailable |
| IndexedDB (via Dexie) | Native | Structured data | Metadata, threads, notes, settings |

**Storage Strategy:**
1. Desktop: FSA for files + Dexie for metadata
2. Mobile: IndexedDB only (all data)
3. Never mix: Decision made at project creation, not per-operation

### AI Integration

| Technology | Version | Purpose | Why |
|------------|---------|---------|-----|
| TanStack AI SDK | 0.2.2 | AI provider abstraction | Type-safe tools, streaming, multi-provider |
| @tanstack/ai-client | 0.2.2 | Client hooks | `useChat`, client-side streaming |
| @tanstack/ai-anthropic | 0.2.0 | Anthropic adapter | Claude models |
| @tanstack/ai-openai | 0.2.1 | OpenAI adapter | GPT models |
| @tanstack/ai-gemini | 0.3.2 | Google adapter | Gemini models |
| @tanstack/ai-ollama | 0.3.0 | Local models | Ollama for privacy |
| @xenova/transformers | 2.17.2 | Client-side embeddings | In-browser RAG without server calls |

**AI Architecture:**
- TanStack AI SDK for provider abstraction (not Vercel AI SDK - too server-centric)
- Client-side embeddings via Transformers.js (privacy, no API costs)
- Local vector search via Orama (IndexedDB-backed)
- Suggest mode by default for AI actions

## Alternatives Considered

| Category | Recommended | Alternative | Why Not |
|----------|-------------|-------------|---------|
| Framework | TanStack Start | Next.js | Already adopted TanStack, better SSR control |
| State | Zustand | Redux Toolkit | Zustand is simpler, slices pattern sufficient |
| State | Zustand | Jotai | Similar capabilities, Zustand already adopted |
| DB | Dexie | Raw IndexedDB | Dexie's API is much cleaner, migrations built-in |
| AI SDK | TanStack AI | Vercel AI SDK | TanStack more client-side friendly, type-safe tools |
| Editor | Monaco | CodeMirror | Monaco is VS Code engine, better LSP support |
| Notes | BlockNote | Tiptap | BlockNote has better block-based UI, AI integration |

## Version Pinning Strategy

| Category | Strategy | Reason |
|----------|----------|--------|
| TanStack | Pin exact | Router/Start versions must match |
| React | Pin major | 19.x for concurrent features |
| Zustand | Pin major | v5 has breaking changes from v4 |
| Dexie | Pin major | Schema migrations may break |
| Others | Use `^` | Patch/minor updates acceptable |
