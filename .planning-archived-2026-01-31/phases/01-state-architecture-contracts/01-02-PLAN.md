  <files>.planning/architecture/SYNC-PATTERNS.md</files>
  <action>
Document synchronization patterns for the dual storage system.

Sections:
1. **Desktop (FSA) Sync Pattern**
   - FSA is source of truth for files
   - Dexie stores metadata, handles, cache
   - Sync on: project open, file change, external edit detection
   
2. **Non-Desktop (IndexedDB) Sync Pattern**
   - Dexie is source of truth for everything
   - No external sync needed
   - Virtual file system in browser

3. **Cross-Layer Sync**
   - Zustand ← Dexie hydration (on mount)
   - Dexie → Zustand (via useLiveQuery)
   - FSA → Event Bus → UI refresh

4. **Conflict Resolution**
   - Last-write-wins for UI state
   - Version-based for persisted data
   - Timestamp-based for file content

Include decision tree:
"Where should this sync happen?"
- Is it UI-only sync? → Zustand subscription
- Is it data sync? → useLiveQuery
- Is it file sync? → Event bus + gateway
  </action>
