# ado-planning

Execute ADO Phase 2: Planning - Architecture design, story creation, and task breakdown.

## Overview

This command initiates the **Planning Phase** of the ADO development lifecycle. It transforms discovery findings into concrete architectural decisions, user stories, and implementation tasks.

## Prerequisites

- **Discovery phase completed** (Phase 1)
- Gate 1 validation passed
- Research cache available from discovery
- Requirements and constraints documented

## Usage

```
/ado-planning [focus]
```

**Parameters:**
- `focus`: Optional architectural focus (e.g., "database schema", "API design", "component architecture")

## Phase 2: Planning Workflow

### Step 1: Load Workflow
1. **Load workflow configuration** from `.bmad/ado/workflows/ado-planning/workflow.yaml`
2. **Read checklist** from `.bmad/ado/workflows/ado-planning/checklist.md`
3. **Load discovery outputs** from `docs/ado-artifacts/ado-phase-outputs/discovery/`

### Step 2: Architecture Design
1. **System architecture**:
   - Component diagram and relationships
   - Data flow design
   - Integration patterns
   - Technology stack decisions

2. **Technical decisions**:
   - Framework and library selection
   - Database schema design
   - API contract specifications
   - State management approach

3. **Architectural constraints**:
   - Performance requirements
   - Scalability considerations
   - Security requirements
   - Maintainability standards

### Step 3: Story Creation
1. **Generate user stories** using `*create-story`:
   - Feature-based stories
   - Technical stories (infrastructure, tooling)
   - Bug fix stories
   - Technical debt stories

2. **Story structure**:
   ```
   ## Story: [Title]
   - **ID**: ADO-[Phase]-[Number]
   - **Type**: Feature | Technical | Bug | Debt
   - **Priority**: High | Medium | Low
   - **Effort**: S | M | L | XL
   - **Description**: [User story]
   - **Acceptance Criteria**: [Testable conditions]
   - **Dependencies**: [Prerequisites]
   - **Definition of Done**: [Completion criteria]
   ```

3. **Story prioritization**:
   - Critical path identification
   - Dependency mapping
   - Risk-based ordering

### Step 4: Task Breakdown
1. **Technical specifications** using `*tech-context`:
   - Detailed implementation guides
   - API endpoint specifications
   - Database schema with migrations
   - Component specifications

2. **Implementation tasks**:
   - Each story broken into tasks
   - Tasks sized appropriately (1-3 day chunks)
   - Dependencies clearly marked
   - Acceptance criteria defined

### Step 5: Gate 2 Validation
Before proceeding to Implementation phase, verify:
- [ ] Architecture approved and documented
- [ ] All user stories created with acceptance criteria
- [ ] Technical specifications completed
- [ ] Task breakdown complete
- [ ] Dependencies mapped
- [ ] Risk mitigation planned

## Story Generation

Stories are generated using multiple inputs:
- Requirements from discovery phase
- Architectural decisions
- Dependencies identified
- Risk assessments
- Success criteria

### Story Template Location
- Template: `.bmad/ado/templates/story-template.md`
- Generated by: `ado-create-story` workflow

### Story Types

**Feature Stories**
```
As a [user type], I want [goal] so that [benefit]
```

**Technical Stories**
```
Implement [technical component] to support [capability]
```

**Bug Fix Stories**
```
Fix [issue] affecting [impact area] to restore [functionality]
```

**Technical Debt Stories**
```
Refactor [component] to [improvement] for [benefit]
```

## Story Backlog

Stories are organized into a sprint-ready backlog:
```
## Sprint Backlog

### Sprint [Number]
**Goal**: [Sprint objective]
**Capacity**: [Story points]

#### Ready for Implementation
- [ ] Story 1 (High, M points)
- [ ] Story 2 (High, L points)
- [ ] Story 3 (Medium, M points)

#### Backlog
- [ ] Story 4 (Medium, S points)
- [ ] Story 5 (Low, M points)
```

## Success Criteria

Planning phase is complete when:
- Architecture documented and approved
- All user stories created with acceptance criteria
- Technical specifications complete
- Task breakdown sufficient for implementation
- Dependencies mapped and understood
- Sprint backlog ready
- Gate 2 validation checklist 100% complete

## Examples

### Plan Feature Implementation
```
/ado-planning AI chat feature with streaming
```
**Result**: Architecture design for AI chat feature including API design, database schema, and story breakdown.

### Plan Refactoring
```
/ado-planning refactor agentic-coder pipeline
```
**Result**: Planning phase for pipeline refactoring with architectural decisions and task breakdown.

### General Planning
```
/ado-planning
```
**Result**: General planning workflow - uses existing discovery outputs to create architecture and stories.

## Common Use Cases

1. **Feature Planning**: Design system architecture, create user stories, define implementation tasks
2. **Refactoring Planning**: Analyze current state, design target architecture, plan migration
3. **Bug Fix Planning**: Understand root cause, design solution, create fix stories
4. **Technical Debt Planning**: Prioritize debt, plan refactoring, schedule improvements

## Integration with ADO

- **Previous Phase**: `ado-discovery` (Phase 1)
- **Next Phase**: `ado-implementation-loop` (Phase 3)
- **Prerequisites**: Gate 1 validation passed
- **Gate**: Must pass Gate 2 before proceeding to Implementation
- **Workflows**: Uses `ado-create-story` and `ado-tech-context`
- **Agents**: Primarily `ado-architect` and `ado-scrum-master`

## Story Dependencies

Stories may have dependencies:
- **Sequential**: Must complete in order
- **Parallel**: Can complete simultaneously
- **Conditional**: Only if other conditions met

Dependency graph is maintained in the sprint tracker.

## Notes

- **Architecture first** - design before implementation
- **Stories are testable** - each story has clear acceptance criteria
- **Task breakdown** - enough detail to estimate and implement
- **Dependency mapping** - understand relationships and order
- **Risk mitigation** - plan for known risks and blockers
