# Internationalization (i18n) Documentation

## Overview

The Via-gent platform uses i18next for internationalization, supporting English (en) and Vietnamese (vi) languages. All UI strings are externalized into JSON files for easy translation and maintenance.

## File Structure

| File | Lines | Purpose |
|------|-------|---------|
| `config.ts` | 28 | i18next initialization and configuration |
| `en.json` | 1161 | English translation strings |
| `vi.json` | - | Vietnamese translation strings |
| `LocaleProvider.tsx` | - | React context provider for locale |
| `__tests__/config.test.ts` | - | i18n configuration tests |
| `en/rag.json` | - | RAG-specific English strings |
| `vi/rag.json` | - | RAG-specific Vietnamese strings |

## Configuration

### i18next Initialization

```typescript
// src/i18n/config.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

import en from './en.json';
import vi from './vi.json';

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      en: { translation: en },
      vi: { translation: vi },
    },
    fallbackLng: 'en',
    interpolation: {
      escapeValue: false, // React already safes from xss
    },
    detection: {
      order: ['localStorage', 'navigator'],
      caches: ['localStorage'],
      lookupLocalStorage: 'i18nextLng',
    },
  });

export default i18n;
```

### Key Configuration Options

| Option | Value | Purpose |
|--------|-------|---------|
| `fallbackLng` | `'en'` | Default language when translation not found |
| `interpolation.escapeValue` | `false` | React handles XSS protection |
| `detection.order` | `['localStorage', 'navigator']` | Language detection order |
| `detection.caches` | `['localStorage']` | Cache preference in localStorage |

## Translation Key Patterns

### Basic Keys

```json
{
  "actions.cancel": "Cancel",
  "actions.save": "Save",
  "actions.delete": "Delete",
  "common.close": "Close"
}
```

### Nested Keys

```json
{
  "agents.config": {
    "tabs": {
      "basic": "Basic",
      "workspace": "Workspace",
      "advanced": "Advanced"
    },
    "description": "Configure your AI agent settings"
  }
}
```

### Pluralization

```json
{
  "citation.badge.ariaLabel_one": "{{count}} citation",
  "citation.badge.ariaLabel_other": "{{count}} citations",
  "memory.messages.count_one": "{{count}} message",
  "memory.messages.count_other": "{{count}} messages"
}
```

### Interpolation

```json
{
  "agents.config.fetchFailed": "Failed to fetch models: {{error}}",
  "deepThink.confidence": "Confidence: {{value}}%",
  "time.agoMinutes_one": "{{count}} minute ago"
}
```

## Usage in Components

### Basic Usage

```typescript
import { useTranslation } from 'react-i18next';

function MyComponent() {
  const { t } = useTranslation();
  
  return <button>{t('actions.save')}</button>;
}
```

### With Interpolation

```typescript
function ErrorComponent({ error }: { error: string }) {
  const { t } = useTranslation();
  
  return <p>{t('agents.config.fetchFailed', { error })}</p>;
}
```

### With Pluralization

```typescript
function Badge({ count }: { count: number }) {
  const { t } = useTranslation();
  
  return (
    <span>
      {t('citation.badge.ariaLabel', { count })}
    </span>
  );
}
```

### Nested Keys

```typescript
function AgentConfig() {
  const { t } = useTranslation();
  
  return (
    <div>
      <h2>{t('agents.config.description')}</h2>
      <button>{t('agents.config.tabs.basic')}</button>
    </div>
  );
}
```

## Locale Provider

```typescript
// src/i18n/LocaleProvider.tsx
import { LocaleProvider as AntDLocaleProvider } from 'antd';
import enUS from 'antd/locale/en_US';
import viVN from 'antd/locale/vi_VN';

function LocaleProvider({ children, locale }) {
  const antdLocale = locale === 'vi' ? viVN : enUS;
  
  return (
    <AntdLocaleProvider locale={antdLocale}>
      {children}
    </AntdLocaleProvider>
  );
}
```


## Language Detection

The application detects language in this order:

1. **localStorage**: Previously selected language
2. **navigator.language**: Browser language preference
3. **fallbackLng**: 'en' (English)

## Extracting Translation Keys

### i18next Scanner Configuration

```javascript
// i18next-scanner.config.cjs
const fs = require('fs');
const path = require('path');
const parser = require('i18next-scanner').default;

module.exports = {
  input: ['src/**/*.{ts,tsx}'],
  output: './',
  func: {
    list: ['t', 'i18next.t', 'this.props.t'],
    extensions: ['.ts', '.tsx'],
  },
  trans: {
    component: 'Trans',
    i18nKey: 'i18nKey',
    defaultsKey: 'defaults',
  },
  lngs: ['en', 'vi'],
  ns: ['translation'],
  defaultLng: 'en',
  defaultNs: 'translation',
  resource: {
    loadPath: 'src/i18n/{{lng}}.json',
    savePath: 'src/i18n/{{lng}}.json',
    jsonIndent: 2,
    lineEnding: '\n',
  },
  customizers: {},
  fallbackLng: false,
  debug: false,
  quiet: false,
};
```

### Running Extraction

```bash
pnpm i18n:extract
```

This command:
1. Scans all `.ts` and `.tsx` files
2. Finds all `t()` function calls
3. Updates `en.json` and `vi.json` with new keys
4. Preserves existing translations

## Best Practices

### 1. Use Namespaced Keys

```json
// Good
"agents.config.save": "Save"

// Avoid
"save": "Save"
```

### 2. Avoid Concatenation

```json
// Good
"chat.message.prefix": "Message from",
"chat.message.suffix": "sent at"

// Bad - Don't do this
"chat.message": "Message from {{name}} sent at {{time}}"
```

### 3. Use Pluralization

```json
// Good
"files.count_one": "{{count}} file",
"files.count_other": "{{count}} files"

// Avoid
"files.count": "{{count}} file(s)"
```

### 4. Keep Keys Short but Descriptive

```json
// Good
"citation.sidebar.title": "Citations"

// Avoid (too long)
"citation.sidebar.section.title.displayed.in.the.citations.panel": "Citations"
```

### 5. Provide Context in Comments

When adding new keys, consider adding comments:

```json
{
  // Shown in the tool approval overlay when tool execution is slow
  "toolTimeout.warning.title": "Tool Running Slow"
}
```

## Language Switching

```typescript
import { useTranslation } from 'react-i18next';

function LanguageSwitcher() {
  const { i18n } = useTranslation();
  
  const switchLanguage = (lng: string) => {
    i18n.changeLanguage(lng);
  };
  
  return (
    <select onChange={(e) => switchLanguage(e.target.value)}>
      <option value="en">English</option>
      <option value="vi">Tiếng Việt</option>
    </select>
  );
}
```

## Testing

### Unit Tests

```typescript
// __tests__/config.test.ts
import i18n from '../config';

describe('i18n configuration', () => {
  it('should have English as fallback language', () => {
    expect(i18n.options.fallbackLng).toBe('en');
  });

  it('should have English and Vietnamese resources', () => {
    expect(i18n.options.resources).toHaveProperty('en');
    expect(i18n.options.resources).toHaveProperty('vi');
  });

  it('should translate common actions', () => {
    expect(i18n.t('actions.save')).toBe('Save');
    expect(i18n.t('actions.cancel')).toBe('Cancel');
  });
});
```

## Known Issues and Limitations

1. **Interpolation in Keys**: Complex interpolation requires proper escaping
2. **Nested Objects**: Deep nesting can make keys hard to manage
3. **Dynamic Keys**: Keys generated dynamically are not extractable
4. **Context Support**: i18next context not widely used in codebase

## Developer Notes

1. Run `pnpm i18n:extract` after adding new translation keys
2. Ensure Vietnamese translations are culturally appropriate
3. Test both English and Vietnamese in all components
4. Use consistent terminology across translations
5. Avoid hardcoded strings; always use `t()` function
