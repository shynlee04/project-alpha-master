## Root Cause Analysis

### Issue 1: Spike Routes Not Registered

**File**: `src/routeTree.gen.ts`
**Problem**: TanStack Router's file-based routing did not pick up spike routes

**Why This Happened**:
1. Spike files are in `src/routes/-spike/` (with `-` prefix)
2. The `-` prefix is documented to "exclude them from file-based routing type system"
3. However, this means they are NOT accessible at runtime unless manually registered

**Evidence from spike/__root.tsx**:
```typescript
// @ts-nocheck
// Spike Routes - Isolated Development Area
//
// These routes use manual route definitions to avoid TanStack Router's
// file-based routing type system. The `-` prefix excludes them from the
// main route tree generation, but they still work at runtime.
```

**Contradiction**: The comment says "they still work at runtime" but they DO NOT.

### Issue 2: Duplicate Dev Server Processes

**Processes Running**:
```
PID 50879: node .../vite.js dev --port 3000
PID 43127: node .../vite.js dev --port 3000
```

**Problem**: Two vite processes on same port 3000
**Impact**: May cause unpredictable behavior, hot module replacement issues

### Issue 3: Spike Architecture Mismatch

**Documentation Reference**:
- `spike-core-manifest-2026-01-16.md`: Plans spike in `spike/` directory
- `spike-architecture-design-2026-01-16.md`: Plans spike in `routes-spike/` directory
- **Actual Implementation**: Spike in `src/routes/-spike/`

**Conclusion**: The actual spike implementation does not match either planned architecture.
