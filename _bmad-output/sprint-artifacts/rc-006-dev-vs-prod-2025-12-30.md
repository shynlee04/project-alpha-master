## Root Cause Analysis

### ACTUAL ROOT CAUSE: Vite Dev Server SSR Pre-bundling Issue

**Critical Discovery**: The routes **WORK IN PRODUCTION** but **FAIL IN DEV MODE**.

**Issue**: Vite's SSR pre-bundling in dev mode cannot resolve certain path alias patterns, causing 500 errors. The production build uses a different bundling strategy that works correctly.

## Technical Analysis

### Why Dev Server Fails

**Vite SSR Pre-bundling Error**:
```
Failed to run dependency scan. The following dependencies are imported but could not be resolved:
  @/components/notes (imported by src/routes/notes.lazy.tsx)
  @/components/knowledge (imported by src/routes/knowledge.lazy.tsx)
  @/components/study (imported by src/routes/study.lazy.tsx)
```

Even with direct imports, Vite dev server's SSR module resolution has issues with the `@/` path alias in certain contexts.

### Why Production Works

TanStack Start's production build uses a different bundling strategy:
1. **Vite Build**: Uses Rollup for production bundling
2. **Module Resolution**: Different resolution strategy that handles path aliases correctly
3. **SSR Generation**: Server-side rendering works correctly in production mode

### Potential Fix (Not Implemented)

The issue is in the interaction between:
1. `vite-tsconfig-paths` plugin (line 74-76 in vite.config.ts)
2. TanStack Start's SSR environment
3. Vite's dependency pre-bundling in dev mode

**Possible Solutions**:

2. Add explicit module resolution configuration for SSR mode
3. Use a different development server configuration

## Insights & Lessons Learned

### 1. Always Test Production Build
When investigating "inaccessible" routes, I should have tested the production build FIRST. This would have immediately revealed that the issue was dev-mode-specific.

### 2. User Feedback Pattern
When the user repeats the **exact same feedback** multiple times, it means:
- ❌ I'm fixing the wrong things
- ❌ I need to investigate deeper, not just fix surface issues
- ❌ I need to actually TEST the runtime behavior, not just fix code patterns

### 3. Iteration Anti-Pattern
**What I Did Wrong**:
- Iter 1: Fixed barrel exports → Build succeeded → Assumed fixed
- Iter 2: Standardized imports → Build succeeded → Assumed fixed
- Iter 3: Added i18n keys → Build succeeded → Assumed fixed
- Iter 4: Actually tested runtime → Found REAL issue

**What I Should Have Done**:
- Iter 1: Test runtime with `curl` or browser → Found 500 error immediately
- This would have saved 3 wasted iterations

### 4. Build Success ≠ Runtime Success
Just because `pnpm build` succeeds doesn't mean the routes work in dev mode. The production bundler (Rollup) handles things differently than Vite's dev server.
