## Key Insights

### 1. Runtime vs. Build-Time Issues
- **Previous fixes**: Addressed build-time type safety and architectural patterns
- **Actual issue**: Runtime i18n key missing causing component failures
- **Lesson**: When user says "completely not accessible", check for runtime crashes first

### 2. i18n Key Extraction Gap
- The project uses `pnpm i18n:extract` to auto-extract translation keys
- However, NotesPage.tsx was using keys that were never extracted
- **Gap**: No validation that component-used keys exist in translation files
- **Recommendation**: Add i18n key validation to build pipeline

### 3. Component→Translation File Mapping
Current workflow:
1. Developer adds `t('notes.title', 'Notes')` to component
2. Developer must MANUALLY add key to en.json and vi.json
3. Run `pnpm i18n:extract` to update extraction

**Problem**: Step 2 is easily forgotten, causing runtime errors
**Solution**: Consider automated validation in pre-commit hook or build pipeline

## Database Schema Note

**Observation**: Notes table is only added in database version 15 ([dexie-db.ts:1093](src/lib/state/dexie-db.ts#L1093))

**Potential Impact**: If user's IndexedDB is at version <15, the notes table won't exist and may cause initialization errors

**Status**: Not blocking current fix (i18n was the immediate issue)
**Recommendation**: Verify database migration logic properly upgrades older databases to version 15
