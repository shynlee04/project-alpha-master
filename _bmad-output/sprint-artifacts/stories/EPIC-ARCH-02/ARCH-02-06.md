## Problem Statement

BlockNote editor is currently deeply integrated into NotesPage with workspace-specific state management. To support the new project-centric architecture, it must be extracted into a self-contained plugin that:

1. Receives project context from ProjectContextProvider
2. Works with both FSA (markdown files) and IndexedDB (virtual storage)
3. Syncs with external editors (FSA mode only)
4. Handles conflict resolution when external changes detected
5. Implements FeaturePlugin interface per ADR-034

**NotesPlugin.tsx** (~350 lines):
```typescript
import React from 'react';
import { FileText } from 'lucide-react';
import type { FeaturePlugin, PluginMainProps } from '@/domain/interfaces/feature-plugin.interface';
import { useProjectContext } from '@/infrastructure/context/project-context';
import { useNotesPlugin } from './useNotesPlugin';
import { NoteEditor } from '@/presentation/components/notes/NoteEditor';

// Main component
function NotesComponent({ width, height }: PluginMainProps) {
  // Get context from provider
  const projectContext = useProjectContext();
  
  // Use plugin-specific state
  const pluginState = useNotesPlugin(projectContext);
  
  return (
    <div style={{ width, height }}>
      <NoteEditor {...pluginState} />
    </div>
  );
}

// Plugin definition
export const notesPlugin: FeaturePlugin = {
  id: 'notes',
  name: 'Notes',
  icon: React.createElement(FileText, { size: 16 }),
  description: 'BlockNote editor for rich content',
  requirements: {
    storageType: 'any', // Works with FSA and IndexedDB
    deviceType: 'any', // Works on desktop and mobile
    minWidth: 300, // Minimum 300px width
    maxInstances: 1, // Only one notes editor per project
  },
  MainComponent: NotesComponent,
  onMount: async (context) => {
    console.log('[NotesPlugin] Mounted for project:', context.projectId);
  },
  onUnmount: async () => {
    console.log('[NotesPlugin] Unmounted');
  },
  onProjectChange: async (newProjectId) => {
    console.log('[NotesPlugin] Project changed to:', newProjectId);
  },
};
```

## Notes

**Special Considerations:**

1. **BlockNote Complexity:** NoteEditor.tsx is 1063 lines with 16 custom block types. Do NOT attempt to rewrite the editor - extract it as-is and add ProjectContext integration layer.

2. **Markdown Sync (FSA Mode):**
   - Load: `gateway.read('/notes/note.md')` → parse markdown → load into BlockNote
   - Save: `editor.getMarkdown()` → `gateway.write('/notes/note.md', data)`
   - Watch: `gateway.watch(callback)` → detect external changes → show conflict dialog

3. **IndexedDB Storage (Mobile Mode):**
   - Load: Query Dexie notes table by projectId
   - Save: Update Dexie notes record
   - No external sync needed (single source of truth)

4. **Conflict Resolution:**
   - When gateway.watch detects external change:
     - Show dialog: "External changes detected. Keep your version or reload from file?"
     - If reload: Clear editor, reload from gateway.read()
     - If keep: Mark file as dirty, user must manually save

5. **Backward Compatibility:**
   - Keep NoteEditor component in original location as facade
   - Re-export from plugin to maintain existing imports
   - No breaking changes to other components using NoteEditor

**Risk Mitigation:**

- **Complexity Risk:** BlockNote has many dependencies - use facade pattern to isolate plugin layer
- **Sync Race Condition:** Debounce file watch events (500ms) to avoid multiple conflict dialogs
- **TypeScript Complexity:** Use `BlockNoteBlock = any` (already documented in NoteEditor.tsx)
