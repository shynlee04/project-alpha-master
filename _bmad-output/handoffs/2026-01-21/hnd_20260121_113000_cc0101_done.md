## 1. Context Summary

**Story:** CC-01-01 - Remove useLiveQuery hook from NotesWorkspaceDefault component
**Epic:** EPIC-CC-01 (Fix Hooks Error - Phase 1)

**Completed Work:**
Successfully removed the `useLiveQuery` hook from `src/routes/notes.lazy.tsx` that was violating React's rules of hooks and causing "Rendered fewer hooks than expected" error.

**Problem Fixed:**
The `NotesWorkspaceDefault` component was using `useLiveQuery` hook conditionally (only when `platform.canAccessFSA` is true), which violates React's rules of hooks. This prevented all users from accessing the Notes workspace on both desktop and mobile.

**Solution Implemented:**
Replaced conditional logic with platform-based early returns:
- Desktop with FSA → return `<ProjectPickerDialog />` directly (no state needed)
- Mobile → existing browser-mode logic via `getOrCreateBrowserModeProject()`

function NotesWorkspaceDefault() {
  const navigate = useNavigate();
  const platform = getPlatformContract();
  const [project, setProject] = useState<Project | null>(null);
  const welcomeNoteCreatedRef = useRef(false);

  // ✅ Desktop with FSA → show picker directly (no state)
  if (platform.canAccessFSA) {
    return (
      <div className="h-full flex items-center justify-center bg-background">
        <ProjectPickerDialog
          open={true}
          onOpenChange={(open) => {
            if (!open) {
              navigate({ to: '/' });
            }
          }}
          targetWorkspace="notes"
          onCreateNew={() => {
            navigate({ to: '/' });
          }}
        />
      </div>
    );
  }

  // ✅ Mobile/tablet → use browser-mode
  useEffect(() => {
    import('@/lib/workspace/browser-mode').then(
      async ({ getOrCreateBrowserModeProject, BROWSER_MODE_PROJECT_ID }) => {
        const browserProject = await getOrCreateBrowserModeProject();
        // ... existing browser-mode logic preserved
      }
    );
  }, [platform.canAccessFSA]);  // ✅ No hook dependency
}
